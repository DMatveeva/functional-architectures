Изучила модуль "Порты и Адаптеры", а также материал "Что такое Функциональная архитектура".

Поняла, что у нас в проекте практически нет чистых функций:)
Даже там, где в этом нет никакой необходимости. 
Например, есть  метод для обработки входящего сообщения processMessage(message). 
В нем нужно сделать валидацию сообщения, распарсить его, преобразовать в объекты нашей доменной модели и сохранить в базу данных.
Валидация и преобразование вполне могли бы быть чистыми функциями, ведь их результат всегда одинаков для одних и тех же входных сообщений, и нам не нужно делать запросы в БД или сторонние системы для этого.
Но у нас метод validate(message) на каждое ошибочное поле выбрасывает исключение. А выше по стеку мы его ловим в try-catch.

Так же и метод для преобразования сообщения в объекты нашей доменной модели parse(message). 
Например, если мы ожидаем в сообщении одну котировку, а пришло несколько, мы делаем throws new IllegalArgumentException("Only one qoute expected."); 
В итоге куча исключений выбрасывается в разных местах.

При реализации обработки нового типа сообщения, я сделала эти функции чистыми. 
validate возвращает объект ValidationResult с описанием всех ошибок, не выбрасывая никаких исключений.
Метод parse возвращает объект QuoteParsingResult, с полями List<Quote> и List<String> errors. 
А в методе processMessage обрабатываются возможные ошибки.

Также, в дизайне от аналитика была формулировка "Если в сообщении есть котировка с названием "X", то необходимо сделать http-запрос в другую систему, извлечь из ответа значение maxValue, и сравнить со значением котировки quoteValue. 
Если quoteValue > maxValue, необходимо отправить письмо на почту команде поддержки."

Если писать код четко согласно дизайну, то это был бы метод с циклом по котировкам, в теле цикла проверка 
'''
if(quote.name().equals("X")) {
  BigDecimal max = getMaxValueByHttp();
  if(max > quote.value()) {
     sendMail(...);
     throws new IllegalArgumentException("Qoute value is out of range");
}
}
'''
